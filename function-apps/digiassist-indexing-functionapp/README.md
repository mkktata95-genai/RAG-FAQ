# digiassist-indexing-functionapp

One Azure Function App with four functions that write documents into two Azure AI Search indexes:

- **Indexer**: takes the scraped JSON (`output/scraped-data/`) and syncs it into the main FAQ index.
- **Templated questions**: takes the templated-questions Excel (most frequently asked questions with approved answers, citations and CTA links) and syncs it into a dedicated index. The query side searches that index first and uses an entry when the similarity is at or above 0.75; otherwise it falls back to the normal RAG.

The scripts are unchanged (`chunk_embed_index_funcV1.py`, `templated_job.py`). This repo only adds the hosting layer: `function_app.py`, `src/indexer_job.py`.

The two indexes are created and owned by the platform team. This app only writes documents (role: Search Index Data Contributor). It never creates, deletes or aliases an index. Needs no internet access.

## How it behaves

**Indexer**
- A new `royal_london_faq_approved_*.json` in `output/scraped-data/` starts a sync into the index named by `AZURE_SEARCH_INDEX_NAME`. The `_failures.json` sidecar is read with it if present (failed URLs keep their old chunks) and never triggers a run itself.
- Sync mode: new and changed chunks are uploaded, removed pages are deleted. A run that would remove more than 10% (`INDEXER_MAX_REMOVAL_RATIO`) stops before any write; override with `allow_mass_removal` in the queue message.
- One build at a time (internal lock).
- Rollback = re-run from an earlier scraped JSON in blob storage.

**Templated questions**
- The Excel is the **full source of truth**. After a run the index holds exactly the active rows of that file.
- New or changed rows are upserted (same id = overwrite). Ids no longer in the file are deleted **after** the upload succeeds.
- A single invalid row refuses the whole run before anything is written.
- Mass-deletion protection: a run that would delete 3 or more entries and more than 50% of the index stops before any write. Override with `allow_mass_removal` (queue message) or `--allow-mass-removal` (local).
- Rollback = upload the previous Excel again.

## Functions

| Function | Trigger | What it does |
|---|---|---|
| `index_on_scrape` | Blob `output/scraped-data/{name}` (main JSON only) | Sync that JSON into the FAQ index |
| `index_on_request` | Queue `index-requests` | Sync a named JSON or the newest one. Body: any text = newest; `{"file": "royal_london_...json", "allow_mass_removal": true}`; text containing `allow_mass_removal` also sets the override |
| `templated_on_upload` | Blob `input/templated-questions/{name}` (.xlsx only) | Sync that Excel into the templated index |
| `templated_on_request` | Queue `templated-requests` | Sync a named file or the newest .xlsx. Body (all optional): `{"file": "x.xlsx", "allow_mass_removal": true, "dry_run": true}` |

## Excel layout (templated)

One sheet (the first). Header row, then one row per question. Column names are case-insensitive.

| Column | Required | Notes |
|---|---|---|
| `id` | no | Blank = generated from the question (`q-<hash>`). Reword the question and the id changes (old entry removed). Set an id to keep it stable. |
| `question` | yes | The question that is embedded and matched |
| `answer` | yes | Max 250 characters (warning above 180) |
| `intent` | no | `grounded` (default), `direct`, `blocked` |
| `scenario` | no | `standard` (default), `not_applicable`, `advice_seeking`, `distress`, `escalation_and_handoff`, `account_action` |
| `advice_boundary` | no | `true` / `false` (default false) |
| `active` | no | `N` retires the row: removed from the index on the next run |
| `citation_1_title`, `citation_1_url` ... `citation_3_*` | no | 0 to 3 pairs. https URLs on royallondon.com only |
| `cta_1_label`, `cta_1_url` ... `cta_3_*` | no | 0 to 3 pairs. Same URL rule |

`sample_templated.xlsx` (generated by `make_sample_xlsx.py`) shows the layout. The templated index needs these fields: `id` (key), `question`, `question_vector` (cosine, same dimensions), `response_json`, `source_urls` (Collection(String)), `created_at` (DateTimeOffset). A preflight check fails the run with a clear message if the index is missing or does not match.

## App settings

| Setting | Example |
|---|---|
| `FUNCTIONS_WORKER_RUNTIME` | `python` |
| `DataStorage__blobServiceUri` | storage blob URL (Azure, managed identity). Local: `DataStorage=UseDevelopmentStorage=true` |
| `AzureWebJobsStorage` | host storage (Azure: identity-based `AzureWebJobsStorage__*` settings) |
| `AZURE_SEARCH_ENDPOINT` | `https://<search>.search.windows.net` |
| `AZURE_SEARCH_INDEX_NAME` | FAQ index name (platform-created). **Local: a TEST index** |
| `AZURE_SEARCH_TEMPLATED_INDEX_NAME` | templated index name (platform-created) |
| `AZURE_SEARCH_SEMANTIC_CONFIG` | semantic config on the FAQ index |
| `AZURE_OPENAI_ENDPOINT` | `https://<openai>.openai.azure.com` |
| `AZURE_OPENAI_EMBEDDING_DEPLOYMENT` | `text-embedding-3-large` |
| `AZURE_OPENAI_EMBEDDING_DIMENSIONS` | `1536`. Shared by both jobs, so both indexes must use 1536 |

The indexer and templated jobs fail at the start of a run if a required setting is missing.

Optional tuning (defaults are fine): `INDEXER_INPUT_PREFIX` (`scraped-data/`), `INDEXER_MAX_REMOVAL_RATIO` (0.10), `PIPELINE_RETRY_ATTEMPTS` (5), `TEMPLATED_INPUT_PREFIX` (`templated-questions/`), `TEMPLATED_MAX_REMOVAL_RATIO` (0.5), `TEMPLATED_ANSWER_MAX_CHARS` (250), `TEMPLATED_ALLOWED_HOSTS` (royallondon.com), `TEMPLATED_RETRY_ATTEMPTS` (4).

Roles (managed identity): host storage Blob Data Owner + Queue Data Contributor + Table Data Contributor; data storage Blob Data Reader (Contributor only if templated needs to write); Search Index Data Contributor; Cognitive Services OpenAI User.

## 9. Deploy and operate

- Pipeline: `Pipelines/azure-pipelines-func-indexing-platform.yml` (platform template, `pythonVersion: "3.11"`). Set `appName` to the real Function App name agreed with DevOps.
- Index a scrape: it starts by itself when the Scraper (webingest app) uploads a JSON. To run by hand, send `{"file": "royal_london_faq_approved_httpV1_<time>.json"}` (or `run` for the newest) to `index-requests`.
- Update the templated Excel: upload the **complete** file to `input/templated-questions/`. The index becomes exactly that file.
- Preview a change without writing: send `{"file": "x.xlsx", "dry_run": true}` to `templated-requests` and read the log.
- Intentional large deletion: add `"allow_mass_removal": true` to the message.
- Log markers: `INDEX_SYNCED` (indexer success), `TEMPLATED_SYNCED` (success), `TEMPLATED_REJECTED` (bad rows, one line per problem), `TEMPLATED_REFUSED` (circuit breaker).
