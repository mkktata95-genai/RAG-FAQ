# digiassist-templated-functionapp

Azure Function App that turns the **templated-questions Excel** (most frequently asked questions, with approved answers, citations and CTA links) into entries in a dedicated Azure AI Search index. The query side searches that index first and uses an entry when the similarity is at or above the threshold (0.75); otherwise it falls back to the normal RAG.

## How it behaves

- The Excel is the **full source of truth**. After a run the index holds exactly the active rows of that file.
- New or changed rows are upserted (same id = overwrite). Ids that are no longer in the file are deleted **after** the upload succeeds.
- A single invalid row refuses the whole run before anything is written (the agent silently ignores a bad entry, so we do not let one in).
- Mass-deletion protection: a run that would delete 3 or more entries and more than 50% of the index stops before any write. Override with `allow_mass_removal` (queue message) or `--allow-mass-removal` (local).
- The index is created and owned by the platform team. This app only writes documents (role: Search Index Data Contributor). It never creates, deletes or aliases an index.
- Rollback = upload the previous Excel again.

## Functions

| Function | Trigger | What it does |
|---|---|---|
| `templated_on_upload` | Blob `input/templated-questions/{name}` (.xlsx only) | Sync that file |
| `templated_on_request` | Queue `templated-requests` | Sync a named file or the newest .xlsx. Body (all optional): `{"file": "x.xlsx", "allow_mass_removal": true, "dry_run": true}` |

## Excel layout

One sheet (the first). Header row, then one row per question. Column names are case-insensitive.

| Column | Required | Notes |
|---|---|---|
| `id` | no | Blank = generated from the question (`q-<hash>`). Reword the question and the id changes (old entry is removed). Set an id to keep it stable. |
| `question` | yes | The question that is embedded and matched |
| `answer` | yes | Max 250 characters (warning above 180) |
| `intent` | no | `grounded` (default), `direct`, `blocked` |
| `scenario` | no | `standard` (default), `not_applicable`, `advice_seeking`, `distress`, `escalation_and_handoff`, `account_action` |
| `advice_boundary` | no | `true` / `false` (default false) |
| `active` | no | `N` retires the row: it is removed from the index on the next run |
| `citation_1_title`, `citation_1_url` ... `citation_3_*` | no | 0 to 3 pairs. https URLs on royallondon.com only |
| `cta_1_label`, `cta_1_url` ... `cta_3_*` | no | 0 to 3 pairs. Same URL rule |

`sample_templated.xlsx` (generated by `make_sample_xlsx.py`) shows the layout.

## App settings

| Setting | Example |
|---|---|
| `AZURE_SEARCH_ENDPOINT` | `https://<search>.search.windows.net` |
| `AZURE_SEARCH_TEMPLATED_INDEX_NAME` | templated index name (created by the platform) |
| `AZURE_OPENAI_ENDPOINT` | `https://<openai>.openai.azure.com` |
| `AZURE_OPENAI_EMBEDDING_DEPLOYMENT` | `text-embedding-3-large` |
| `AZURE_OPENAI_EMBEDDING_DIMENSIONS` | `1536` (must equal the index vector dimensions) |
| `DataStorage__blobServiceUri` | storage blob URL (Azure, managed identity) |
| `AzureWebJobsStorage` | host storage (Azure: identity-based settings) |

Optional tuning (defaults are fine): `TEMPLATED_MAX_REMOVAL_RATIO` (0.5), `TEMPLATED_ANSWER_MAX_CHARS` (250), `TEMPLATED_ALLOWED_HOSTS` (royallondon.com), `TEMPLATED_RETRY_ATTEMPTS` (4).

The index needs these fields: `id` (key), `question`, `question_vector` (cosine, same dimensions), `response_json`, `source_urls` (Collection(String)), `created_at` (DateTimeOffset). A preflight check fails the run with a clear message if the index is missing or does not match.

## 9. Deploy and operate

- Register the pipeline from `Pipelines/azure-pipelines-templated-func.yml` (manual trigger). It deploys `templated.zip` and checks that `templated_on_upload` and `templated_on_request` are registered.
- Update the Excel: upload the **complete** file to `input/templated-questions/`. The index becomes exactly that file.
- Preview a change without writing: send queue message `{"file": "x.xlsx", "dry_run": true}` to `templated-requests` and read the log.
- Intentional large deletion: `{"file": "x.xlsx", "allow_mass_removal": true}`.
- Look for `TEMPLATED_SYNCED` (success), `TEMPLATED_REJECTED` (bad rows, one line per problem) and `TEMPLATED_REFUSED` (circuit breaker) in the log.
